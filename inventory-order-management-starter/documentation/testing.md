## Интеграционные тесты отмены

Тесты используют настоящую PostgreSQL и отдельную базу `inventory_test`.
Новый контейнер PostgreSQL не требуется.

Команды ниже выполняются из каталога `inventory-order-management-starter`,
где находится `go.mod`.

Для запуска тестов нужны Go версии, указанной в `go.mod`, и работающая
PostgreSQL. Для `go test -race` на Linux также нужен C-компилятор
и включённый CGO.

### Подготовка

Запустите PostgreSQL:

```bash
docker compose up -d postgres
docker compose ps
```

Дождитесь состояния `healthy`.

Один раз создайте тестовую базу:

```bash
docker compose exec -T postgres \
  psql -U postgres -d postgres -v ON_ERROR_STOP=1 \
  -c 'CREATE DATABASE inventory_test;'
```

Один раз примените начальную миграцию к новой базе:

```bash
docker compose exec -T postgres \
  psql -U postgres -d inventory_test -v ON_ERROR_STOP=1 \
  < migrations/001_init.up.sql
```

Не запускайте начальную миграцию повторно поверх уже созданных таблиц.
При добавлении новых миграций обновляйте также схему тестовой базы.

Если Docker требует прав администратора, добавляйте `sudo`
перед командами `docker`. Команды `go` запускайте без `sudo`.

### Запуск

В терминале, из которого запускаются тесты, задайте строку подключения:

```bash
export TEST_DATABASE_URL='postgres://postgres:postgres@127.0.0.1:5432/inventory_test?sslmode=disable'
```

Этот адрес подходит при запуске тестов на хосте с опубликованным портом
PostgreSQL `5432`. При другом внешнем порте измените строку подключения.
Указанные учётные данные предназначены для локального окружения проекта.

Запустите тесты отмены:

```bash
go test ./internal/store -run '^TestCancelOrder' -v -count=1
```

Повторите конкурентные сценарии:

```bash
go test ./internal/store \
  -run 'TestCancelOrder/concurrent_same_order|TestCancelOrderSharedProducts' \
  -v -count=20 -timeout=2m
```

Запустите все тесты с детектором гонок и статический анализ:

```bash
go test -race ./... -v -count=1 -timeout=2m
go vet ./...
```

Без `TEST_DATABASE_URL` интеграционные тесты пропускаются (`SKIP`).
Успешный запуск команды с пропущенными тестами не подтверждает
корректность отмены.

Тесты отказываются работать с базой, имя которой отличается
от `inventory_test`. Они создают собственные записи и удаляют
их после выполнения. При принудительном завершении процесса
тестовые записи могут остаться.

### Проверяемые сценарии

- Отмена заказа с несколькими позициями.
- Повторная отмена без повторного возврата остатков.
- Отмена несуществующего заказа.
- Конкурентная отмена одного заказа.
- Конкурентная отмена разных заказов с общими товарами.
- Повторная отмена этих заказов.
- Откат изменений при переполнении остатка одного из товаров.

Тестовые заказы создаются напрямую SQL-запросами, чтобы проверки
`CancelOrder` не зависели от реализации `CreateOrder`.

Детектор `-race` проверяет гонки доступа к памяти Go.
Корректность работы с PostgreSQL проверяется отдельно:
по итоговым остаткам, статусам и возвращаемым ошибкам.
Повторные конкурентные прогоны не являются доказательством
отсутствия всех возможных ошибок конкуренции.
